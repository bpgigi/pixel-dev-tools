# 角色生成回归检查

在没有既往生成历史的新上下文中提供 Skill、一个测试输入、模式和输出目录。每个角色单独生成。`text-only` 案例明确附加“完全不使用任何图片参考”，不加载样板或示例图片；`bundled-reference` 案例遵循默认流程，检查并显式传入一张内置样板。保留实际发给工具的完整提示词、工具名称、图片参数和每次输出。

检查 [prompts.json](prompts.json) 中每个案例的要求，再按下面的统一标准观察结果。每项记 `pass`、`partial` 或 `fail`，附具体原因：

| 项目 | 观察内容 |
| --- | --- |
| 角色要求 | 职业、年龄、衣服、主色和道具符合用户输入；老人不能只依赖白发体现年龄 |
| 比例与表情 | 约两头身、小脸、极简眼睛、短四肢 |
| 五官布局 | 鼻嘴与腮红位置清楚；人类鼻嘴中央没有像鼻孔的分离双红点，不照搬样板的面部标记 |
| 轮廓 | 饱满、连续的阶梯轮廓，帽沿和鞋不尖薄 |
| 像素质感 | 色块连贯，明暗克制；无明显模糊或塑料高光 |
| 构图 | 单人完整全身，道具和脚没有被切断 |
| 输出 | 读取实际尺寸、PNG 格式和透明通道，不凭棋盘格判断 |

分别查看放大图与地图显示尺寸。年龄只判断可读的大致年龄层，不从 Q 版角色推断精确岁数；青年与少年难以区分时如实记为 `partial`。由视觉检查判断美术完成度；不要用颜色数量、文件大小或哈希值替代美术判断。

记录首次输出和修正次数。参考图生成必须另标 `reference-guided`，不能算作纯文字测试。没有执行的案例保持未执行状态；测试输入的存在本身不是通过证据。

生成工具未报告模型名或随机种子时记 `null`。文件哈希只用于确认发布的图片与检查过的文件一致。首次少量测试用于发现失配，不代表经过大规模一致性评测。
